# PWA Foundation — Build 28

## Ownership

Build 28 activates installable PWA behavior only inside `apps/studio`.

The PWA layer is deliberately narrow:

- Web App Manifest owned by `apps/studio/public/manifest.webmanifest`;
- registration helper owned by `apps/studio/src/pwa.ts`;
- service-worker source generated by the audited Vite plugin in `apps/studio/vite.config.ts`;
- cache prefix `gd-studio-shell-`;
- offline behavior limited to the Studio application shell.

## Installability

The manifest declares:

- `id`, `start_url` and `scope` as `./`;
- standalone display mode;
- 192×192 and 512×512 PNG icons;
- no related native application preference.

The Studio registers `./service-worker.js` with scope `./` after the window load event. Registration failure is contained and does not prevent the React application from running.

## Offline app shell

The Vite production build generates `service-worker.js` from the actual build bundle inventory. The service worker precaches:

- the application root;
- built `index.html`;
- Web App Manifest;
- PWA icons;
- generated non-source-map Vite bundle assets.

Navigation requests are network-first with cached `index.html` fallback. Known shell assets are cache-first. Old caches are removed only when their key starts with `gd-studio-shell-`.

## Security and authority boundaries

The Build 28 PWA is not a generic network or persistence authority.

The service worker:

- ignores non-GET requests;
- ignores cross-origin requests;
- handles only navigation fallback or known shell URLs;
- does not connect to GitHub APIs;
- does not connect to the Local Runtime;
- does not store repository context, project files, tokens, secrets or Provider responses.

`networkAuthority`, `storageAuthority`, `projectDataPersistence`, `repositoryContextPersistence`, `localRuntimeTransport`, `githubProviderDirectAccess`, `extensionDirectAccess` and `externalTransport` remain false in Architecture Guardian policy. Cache Storage use exists only as the explicitly scoped PWA app-shell mechanism.

## Deferred authority

Build 28 does not implement:

- Build 29 — Unified Design System;
- Build 30 — IDE Layout;
- Build 31 — Onboarding;
- production PWA packaging — Build 122;
- production hosting/deployment;
- release authority — Build 134.

No production deploy, DNS mutation, browser-store publication, Supabase production mutation, tag or release is authorized by Build 28.
